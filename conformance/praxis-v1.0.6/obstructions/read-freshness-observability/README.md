# Read-freshness observability correction

Praxis v1.0.5 instructed a stateless model to perform a fresh check and a fresh read before revising an already changed path, but its Memory and DecisionView retained only the current document snapshot. Reading unchanged bytes therefore upserted the same snapshot and produced no semantic state change. The executable reproducer bundles the four recorded v1.0.5 source objects and recomputes their Git blob identities without requiring checkout metadata; it reports whether authoritative historical Git objects were available. Release construction requires that historical authentication, while portable source checks do not claim it. Private Poiesis run evidence separately witnessed the resulting repeated-read fixed point. The successor candidate also binds a complete source manifest. Lifecycle proofs from a no-Git export require the receiver to supply the authenticated manifest digest through `PRAXIS_SOURCE_MANIFEST_SHA256`, reject altered or unexpected source bytes, and report the observed manifest identity with no Git-commit claim; only a clean exact repository root may emit `source_identity = git-commit`.

v1.0.6 adds one typed `ReadEvidence` value owned by the EpistemicStrategy. Every `read_file` observation records the exact path plus the current test and conflict epochs, and DecisionView exposes that witness. Pre-effect replacement admission requires a previously changed path to match the latest read path and current epochs. A new full check makes earlier read evidence stale. Every replacement conflict monotonically advances the global conflict epoch and invalidates the prior full-check epoch; recovery requires a fresh full check followed by an exact-path read. After the first conflict, every replacement requires current evidence, so multiple unresolved conflicts cannot erase one another. The model-visible instructions name the exact witness and direct the model to stop rereading once it is current. The implementation lowering identity advances to `agent.epistemics.praxis-zig-working-set.lowering.v2`.

This changes the parent application ID, WASM, Decision Contract, codec, and Machine state schema. It does not change Machine ABI 2, ABL_RNF2, Application ABI 1, Frame 1, Effect protocol 1, host behavior, capability authority, replacement count, changed-file count, or external-effect semantics. The v1.0.6 release is explicitly `praxis-successor-artifact-release/v1`: it binds application artifacts and deterministic/retry/replay/measurement proofs for downstream Poiesis use and makes no new Praxis live-execution or publication claim.
